# 研究节点 (Research Node) 规范

研究节点是 Vibe Research 工作流的基础知识单元，替代原有的"卡片"概念。节点采用"主干-侧枝"（Trunk-Branch）结构组织，旨在构建模块化、问题导向且易于扩展为知识图谱的研究网络。

## 1. 核心定义

*   **研究节点 (Node)**：一个独立的信息单元，包含一个明确的研究问题（Question）及其对应的描述/回答（Description/Answer）。
*   **主干节点 (Trunk Node)**：代表核心研究主题、主要假设或一级研究问题。
*   **侧枝节点 (Branch Node)**：对主干节点的支撑、细化、证据补充或延伸讨论。

## 2. 命名规范

*   **文件名**：`序号-简短关键词.md` (例如: `01-劳动利用不充分定义.md`)
*   **标题 (H1)**：必须以**问句**形式呈现，直击核心逻辑。
    *   *Bad*: 农村青年失业率数据
    *   *Good*: 2018年以来农村青年失业率呈现何种变化趋势？

## 3. 内容结构

每个研究节点文件应包含以下要素：

```markdown
# [问句形式的标题]

**ID**: [节点编号, 如 Q-01]
**Tag**: #[标签1] #[标签2]
**Parent**: [[父节点链接]] (如果是侧枝节点)

## 核心观点 (Key Insight)
[一句话总结该节点的核心发现或论点]

## 详细阐述 (Elaboration)
- **论据/数据**：[支持观点的核心数据或引用]
- **逻辑推演**：[分析过程]
- **未解之谜**：[尚待解决的子问题，可链接到新的侧枝节点]

## 关联节点 (Links)
- [[相关节点A]]
- [[相关节点B]]
```

## 4. 组织原则 (Trunk-Branch)

*   **层级性**：目录结构应反映逻辑层级。
    *   `研究节点/01-核心问题/` (主干)
    *   `研究节点/01-核心问题/01-背景数据/` (侧枝)
*   **原子性**：一个节点只解决一个核心问题。如果问题太复杂，应拆分为子节点。
*   **双链互通**：利用 wiki link `[[]]` 建立节点间的网状联系，不局限于树状结构。

## 5. 适用场景

*   **文献笔记**：将文献拆解为回答特定问题的节点。
*   **数据分析**：独立的实证结果或描述性统计图表。
*   **灵感/假设**：临时的研究想法或待验证的假设。
