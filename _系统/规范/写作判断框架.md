# 写作判断框架 (Writing Judgment Framework)

> 本文件为学术写作Agent提供写作决策方法论参考。
> 教写作Agent"如何判断"写作选择，而非仅"写什么"。

---

## 一、清晰度测试 (Clarity Test)

### 电梯测试

每个段落必须通过"电梯测试"：**能否在30秒内告诉读者这段说了什么？**

**如果不能通过**，可能的原因：
1. 段落承担了太多论点 → 拆分
2. 核心信息被埋在细节中 → 重排，先说结论再说证据
3. 使用了不必要的术语 → 简化表达

### 段落结构标准

每个段落应遵循以下结构：
1. **主题句**：一句话概括本段核心论点
2. **证据/推理**：支持主题句的证据或推理（2-4句）
3. **连接**：与下一段的逻辑关系（可选，不要每段都加）

### 句子清晰度标准

1. 一句话只表达一个完整的想法
2. 如果需要用"并且"、"同时"连接两个并列想法，考虑拆成两句
3. 被动语态只在必要时使用（方法描述、通用陈述）
4. 避免"名词化"——将动词转化为名词（"进行分析"→"分析"）

## 二、读者旅程设计 (Reader Journey Design)

从读者角度规划信息流，确保读者始终知道"我们在哪"和"要去哪"。

### 信息流设计原则

1. **读者此刻知道什么？** → 不要重复读者已经知道的信息
2. **读者需要知道什么？** → 在需要的地方提供必要背景
3. **读者最可能的困惑点在哪？** → 在困惑出现前预防性解释

### 章节级别的读者旅程

**引言**：
- 读者起点：对该领域有基本了解但不是专家
- 目标：让读者理解"为什么这个问题重要"和"这篇论文要做什么"
- 困惑预防：不要在引言中使用未定义的专业术语

**文献综述**：
- 读者起点：已理解研究问题
- 目标：让读者理解"这个领域走到了哪"和"还缺什么"
- 困惑预防：不要列举文献，要对话——指出共识、分歧和Gap

**方法与数据**：
- 读者起点：已理解研究问题和Gap
- 目标：让读者能够评价你的方法选择是否恰当
- 困惑预防：先解释"为什么"选这个方法，再解释"怎么做"

**结果**：
- 读者起点：已理解方法设计
- 目标：让读者能够独立判断结果的可信度
- 困惑预防：先报告核心结果，再讨论稳健性和机制

### 段落级别的读者旅程

每段开头一句话回答读者的预期问题：
- **引言**："为什么要研究这个？" → "房地产价格波动对劳动力市场的影响是一个重要的理论和政策问题..."
- **方法**："你怎么识别因果？" → "本文采用Bartik工具变量策略来识别房地产市场冲击的因果效应..."
- **结果**："你发现了什么？" → "基准回归结果显示，房地产市场冲击显著降低了劳动力的非农就业概率..."

## 三、学科特定语调 (Discipline-Specific Tone)

### 经济学写作惯例

**总体风格**：简洁、直接、以证据为中心

**优先级排序**：
1. **学科规范（硬性）**：经济学论文的结构、术语使用、引用格式
2. **期刊惯例（强）**：目标期刊的具体风格偏好
3. **个人风格（软性）**：作者的语言习惯和表达偏好

### 经济学术语使用原则

1. 使用学科内通用的术语，不创造新术语（除非有充分理由）
2. 首次出现时给出定义
3. 同一概念全文使用同一术语，不轮换同义词
4. 技术性术语只在必要时使用（方法章节可以技术化，引言和结论应通俗化）

### 经济学的"要"与"不要"

| 要 | 不要 |
|----|------|
| 用具体数字说话 | 用模糊形容词（"显著提升"、"大幅增长"） |
| 直接陈述结论 | 先铺垫背景再绕到结论 |
| 用表格展示回归结果 | 用文字描述回归系数 |
| 明确区分相关性和因果性 | 模糊因果语言 |
| 用经济学直觉解释结果 | 只报告统计显著性 |

## 四、修订决策矩阵 (Revision Decision Matrix)

修改时按"影响×成本"排序，决定修改的优先级：

|  | 低成本 | 高成本 |
|---|--------|--------|
| **高影响** | **第一优先**：立即修改 | **第二优先**：规划后修改 |
| **低影响** | **顺手改**：如果方便就改 | **放弃**：不值得投入 |

### 影响评估标准

1. **读者影响**：这个修改是否显著改变读者对论文的理解？
2. **论证影响**：这个修改是否强化或弱化了核心论证？
3. **审稿影响**：这个修改是否会影响审稿人的评价？

### 成本评估标准

1. **时间成本**：完成这个修改需要多少时间？
2. **连锁影响**：这个修改是否需要其他部分跟着改？
3. **风险**：这个修改是否可能引入新的问题？

### 修订时的注意事项

1. 一次只修改一个问题，不要同时修改多个
2. 每次修改后通读相关段落，确保上下文仍然连贯
3. 如果修改导致其他部分不一致，立即标记，不要等到最后
