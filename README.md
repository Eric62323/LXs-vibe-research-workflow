# LXs Vibe Research Workflow v6.0

一个面向经济学实证研究的 Claude Code 协同工作流。通过 **4板块循环**（框架→实证→写作→审查），让研究者在每个阶段都有明确的AI辅助角色和完成标准，逐轮提升论文的严谨性和表达力。

---

## 这个工作流解决什么问题？

用AI做研究，最常遇到三个困境：

1. **AI输出与你的研究主线脱节** —— 聊了很多，但没推进研究本身
2. **写完才发现逻辑漏洞** —— 框架不严谨，实证和理论对不上
3. **AI总是顺着你说** —— 不质疑、不反驳，让你在确认偏误中越陷越深

Vibe Research Workflow 的核心设计就是针对这三个问题：用4板块循环保持主线推进，用完整性关卡确保每一步都扎实，用多角色审稿和魔鬼代言人机制打破AI的谄媚倾向。

---

## 核心架构：4板块循环

```
/框架 ──→ /实证 ──→ /写作 ──→ /审查
  ↑                                  |
  └──── 审查未通过，回到框架修正 ──────┘
```

四个板块各自独立运作，通过完整性关卡衔接。任何时候你都能明确回答"我现在在哪个阶段、下一步做什么"。

### 板块1：概念框架（`/框架`）

**做什么**：把模糊的研究兴趣变成可检验的实证设计。

- **问题界定**：一句话定义 X→Y 关系，明确研究场景
- **文献研究**（3级模式）：
  - 探索级：快速扫描关键词、核心文献、Gap
  - 综述级：PRISMA方法论，6阶段流水线（范围界定→调研→分析→撰写→评审→修订），含偏倚风险评估、证据层级分级
  - 核查级：逐条验证论文中已有引用和论断的准确性
- **理论逻辑**：梳理经济学机制、提出研究假设（H1, H2, ...）
- **因果识别**：绘制DAGs、确定混杂因子、选择识别策略（OLS/FE/DID/IV/RDD）
- **苏格拉底引导**：SCR协议、承诺门、意图检测——不是直接给答案，而是通过提问帮你发现盲点

**完整性关卡**：关卡2.5（文献完成后）+ 关卡4.5（进入实证前）

### 板块2：实证检验（`/实证`）

**做什么**：从数据清洗到稳健性检验的完整实证流程，每一步都有自我校验机制。

```
Phase 0: 数据清洗 → Phase 1: 审查+EDA → Phase 2: 主回归+内部批评
    ↑__________________|                          ↓
    (审查发现问题回到清洗)              Phase 3: 异质性 → Phase 4: 稳健性+内部批评
                                                          ↓
                                                    量化评分关卡（≥80通过）
```

- **Phase 0-1 清洗-审查闭环**：清洗完数据自动审查，发现问题回到清洗环节修正
- **论文类型标注**：自动识别论文类型（reduced-form / structural / DID / IV 等），输出对应审稿人期望清单
- **VERIFY 数值来源核查**：每个关键数值（N、系数、F-stat）必须标注来源log行号，杜绝凭记忆编造
- **Worker-Critic 内部批评**：Phase 2 和 Phase 4 后自动触发，权力分离——跑回归时不审查，审查时不改代码。聚焦识别漏洞、替代解释、样本选择、量级质疑
- **`[LEARN]` 经验标签**：被纠正时自动记录经验，跨会话积累，避免重复犯错
- **量化评分关卡**：满分100分，探索阶段≥60可继续，正式阶段≥80才能进入写作

### 板块3：写作输出（`/写作`）

**做什么**：将框架和实证结果转化为学术文本，7种模式按需选择。

| 模式 | 适用场景 |
|------|---------|
| **full（全流程）** | 首次写作，大纲→初稿→润色→格式→质量检查 |
| **plan（规划引导）** | 不写文字，苏格拉底式逐章提问帮你理清论点和证据 |
| **outline-only** | 只产出详细大纲+证据放置图 |
| **revision** | 输入初稿+审稿意见，输出修改稿+逐条回复信 |
| **revision-coach** | 不改稿，把审稿意见解析为修订路线图 |
| **abstract-only** | 中英文摘要+关键词 |
| **lit-review** | 文献综述章节 |

**特色机制**：
- **风格校准**：学习你过去的论文风格，匹配句长、用词、术语偏好
- **论断溯源审计**：每个判断句标记支撑程度（FULLY/PARTIALLY/UNSUPPORTED），未支撑的列入待办
- **AI高频词检测**：14+个中文AI高频词、19个英文AI高频词自动警告
- **引用忠实度三档标注**：直接引用/概括引用/推断引用，推断引用标记高风险

### 板块4：论证审查（`/审查`）

**做什么**：模拟期刊同行评审，5人审稿团队从不同角度审视论文。

**审稿团队**：
1. **主编（EIC）**：整体适配度和新颖性
2. **方法论审稿人**：配专用计量经济学审查清单（10项：平行趋势、ITT/LATE、弱IV、坏控制、标准误聚类等）+ 图表核实流程（数据一致性+格式质量）
3. **领域审稿人**：文献覆盖、理论框架
4. **视角审稿人**：跨学科启示、政策含义
5. **魔鬼代言人（DA）**：专门找麻烦——但有严格规则：
   - **让步阈值协议**：对每个反驳打1-5分，仅≥4分才让步，让步率≤40%
   - **框架锁定检测**：连续3轮在同一框架内攻击时，强制质疑研究问题本身
   - **"什么能改变我的想法"协议**：每条反对意见必须附带具体的撤回条件

**7维度评分**（0-100分）：方法论严谨性、文献覆盖、论证强度、写作质量、创新性、可复现性、影响力

**审查子循环**：审稿→苏格拉底辅导→修改→再审查。子循环最多3轮，全部维度≥75且无分数回退才算通过。3轮仍未通过建议回到 `/框架` 重构。

## 完整性关卡体系

4个不可跳过的强制性关卡，位于关键节点：

| 关卡 | 位置 | 作用 |
|------|------|------|
| 关卡2.5 | 文献研究完成后 | 确保核心文献已覆盖、Gap基于证据 |
| 关卡4.5 | 框架→实证之间 | 确保假设、DAG、识别策略都已明确 |
| 实证完整性关卡 | 实证→写作之间 | 量化评分（100分制），≥80通过 |
| 审查通过关卡 | 审查→下一Cycle | 7维度全部≥75，无分数回退 |

## 快速开始

1. 将本仓库克隆到 Claude Code 的 skills 目录
2. 创建项目目录与 `项目信息.md`
3. 输入 `/框架`，定义研究问题
4. 按照 **框架 → 实证 → 写作 → 审查 → 重复** 循环推进

---

## 核心原则

1. **以人为主体**：研究决策由你完成，AI是副驾不是代笔
2. **证据优先**：AI只提供检索线索，不虚构文献
3. **结果诚实**：不管是否支持假设，都必须诚实报告
4. **错误不掩盖**：代码报错必须暴露并解决，禁止用 `capture` 吞掉错误
5. **每步可验证**：不写"做XX"，写"做XX → verify: 具体检查项"
